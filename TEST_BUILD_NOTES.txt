BannerlordFG v1.1.3 candidate: GPU / launcher / maintenance safety update
======================================================================

SOURCE BASE
-----------
BannerlordFG-v1.1.3-Install-GPU-BLSE-Source.zip (supplied previous build)
No changes were pushed or published.
OptiScaler pin updated to official nightly-20261116 (GitHub asset SHA256 verified).
Existing nightly-20261112 manifests remain recognized for safe recovery/uninstall.

CHANGES
-------
1. GPU Engine PDH readings remain attached to the verified PID and DXGI LUID.
   A renderer selection needs a native game EXE, live BannerlordFG module
   marker, or verified in-game caller. Launchers can be actual game hosts,
   but unmarked idle launcher windows do not supply renderer evidence.
   Competing adapter readings remain ambiguous; no NVIDIA>AMD>Intel guess.
2. Recognize the original game EXEs, BLSE Launcher, LauncherEx, Standalone,
   and Launcher.Native; always verify the actual executable's full path.
3. A process-lifetime named mutex reports when the in-game module is loaded.
   Installation and uninstallation wait for active game hosts and loaded
   manifest-owned DLLs, not a launcher window alone. Inaccessible module
   information fails closed. Per-file write checks protect against relaunch.
4. Keep automatic OptiScaler runtime-only payload filtering, pinned
   nightly-20261116 and official checksum; preserve upstream setup scripts
   in the existing manual installer mode. Collision checks and hash-owned
   uninstallation are unchanged, with safer rollback of created files.
5. Leave Harmony SetConfig, FPS controls, ReShade and proxy loading intact.
   README warns against renaming BannerlordFG-managed winmm.dll to dxgi.dll.

TESTING IN THIS ENVIRONMENT
---------------------------
Executed: python -m pytest -q tests
Result: 265 passed.

The existing Python tests inspect source contracts. They are NOT Windows
integration tests. A separate executable C# policy/process test harness was
added for real behavioural tests on Windows:
  tests\RunWindowsPolicyTests.cmd
Its scenarios cover Intel+NVIDIA, Intel+AMD, LauncherEx as renderer host,
vanilla launcher as renderer host, independent launcher and game PIDs,
ambiguous GPUs, idle launcher detection, full executable path validation,
process lifetime markers, and managed DLL safety decisions.

- BUILD_WINDOWS.cmd (requires Visual Studio Build Tools, .NET Framework 4.7.2
  targeting pack, and a real Bannerlord installation with TaleWorlds DLLs)
- In-game BLSE, install/uninstall, and OptiScaler/Frame Generation testing
